01. 為什麼我們需要 MCP？

以前 AI 就像被關在房間裡的天才，雖然很聰明，但看不到你電腦裡的資料，也沒辦法幫你按按鈕。

💡 生活化比喻：AI 界的 USB-C 接口
以前每家手機充電線都不同（Lightning、Micro-USB），換設備就要換線；現在統一成 USB-C，一條線就能接螢幕、硬碟與充電器。MCP 就是統一「AI 模型」與「外部工具」之間的通用插頭！

❌ 過去的困境：M × N 整合地獄

如果有 3 款 AI（Claude, GPT, Gemini）要連接 4 種工具（Google Drive, GitHub, Slack, 資料庫），工程師就要寫 3 × 4 = 12 套 客製化連接程式，維護極度痛苦。

✅ 導入 MCP 後：M + N 標準化

Anthropic 於 2024 年底開源此標準。AI 只要支援 MCP、工具也提供 MCP 接口，複雜度瞬間降為 3 + 4 = 7，一次對接、全體通用！

02. MCP 的系統架構與三大角色

MCP 採用「主從式架構（Client-Server）」，由三個角色分工把 AI 與工具串起來。

🍽️ 餐廳點餐比喻： Host 是想吃牛排的顧客，Client 是傳遞菜單的服務生，Server 則是真正負責煎牛排的廚房！

1️⃣ MCP Host（主機）

你直接操作的 AI 軟體。

  • 負責管理對話介面與安全權限
  • 例如：Claude Desktop 桌面版、Cursor 程式編輯器

2️⃣ MCP Client（客戶端）

內建在 Host 裡的通訊員。

  • 負責與 Server 建立「一對一」專屬連線
  • 按照標準格式傳遞請求與結果

3️⃣ MCP Server（伺服器）

連接特定工具的輕量外掛。

  • 對接單一資料源或功能
  • 例如：Google Drive Server、本機檔案 Server

04. 連線方式與「人類把關」安全機制

讓 AI 幫你操作電腦很方便，但如果 AI 誤刪檔案怎麼辦？MCP 在設計時就加入了安全鎖！

🔌 兩種連線模式（Transport）

  • 本機模式（Stdio）：在你的電腦裡直接啟動小程式溝通，資料完全不經過網路，速度最快也最隱私。
  • 雲端模式（HTTP / SSE）：透過網路連接遠端伺服器，適合團隊共用企業資料庫。

🛡️ 人機協作把關（Human-in-the-Loop）

  • 銀行保險箱雙鑰匙原則：AI 雖然可以提議呼叫某個 Tool，但不能偷偷執行。
  • 強制授權彈窗：在寫入檔案或發送訊息前，Host 介面必須跳出確認視窗，等你按下「允許」才會真正執行。

📂 本機檔案整理（Filesystem Server）

直接對 AI 說：「幫我把下載資料夾裡的 PDF 依照科目分類，並整理出大綱」，AI 就能直接讀取並歸檔。

不會寫複雜的 SQL 語法也沒關係，直接用中文問問題，AI 會自動查詢資料表並生成分析圖表。

🌐 網頁自動測試（Puppeteer Server）

AI 可以自己打開無頭瀏覽器、點擊網頁按鈕、截圖檢查你寫的作業網頁有沒有跑版！
